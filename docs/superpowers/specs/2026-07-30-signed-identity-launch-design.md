# 签名跳转实名认证设计

## 目标

允许 new-api 生成的、经过签名和有效期校验的实名认证链接，在 Casdoor 未登录或已登录其他账号时，直接以链接中的目标用户完成实名认证；实名认证资料必须写入该目标用户的 Casdoor 记录。

## 功能边界

- 仅影响带有 `clientId`、`userId`、`redirectUri`、`state`、`timestamp`、`nonce`、`signature` 的签名跳转页面。
- 普通直接访问 `/identity-verification/submit` 且没有签名跳转参数时，继续使用当前 Casdoor 登录用户。
- 不修改 new-api 的 `oidc_id` 绑定关系，不通过修改数据库解决用户错位。
- 不接受仅凭 URL 中的裸 `userId` 操作用户；目标用户必须经过应用、组织、签名、nonce、时间戳和回调地址校验。

## 方案

### 1. 签名跳转校验

Casdoor 收到跳转参数后，加载应用和目标用户，继续校验：

- `clientId` 与应用匹配；
- `userId` 与目标用户 ID 匹配；
- 目标用户属于应用组织；
- `redirectUri` 属于应用允许的回调地址；
- 时间戳、nonce、签名有效。

移除“当前 Casdoor 会话用户必须等于目标用户”的限制。校验成功后，将目标用户 ID、nonce、回调地址和过期时间写入 Casdoor 会话，形成服务端跳转授权上下文。

### 2. 目标用户上下文

实名认证页面加载和提交时优先读取已验证的跳转授权上下文：

- 上下文存在且未过期：所有实名认证查询、提交、审核结果读取都使用上下文中的目标用户；
- 上下文不存在：沿用当前登录用户流程；
- 上下文过期或校验失败：拒绝操作并提示链接无效。

授权上下文只在当前浏览器会话中生效，提交完成或跳转回子应用后清理，避免同一授权被长期复用。

### 3. 前端行为

页面先校验签名跳转参数，再加载目标用户实名认证信息。未登录 Casdoor 时，不因为普通登录检查而阻断签名跳转流程；普通页面访问仍保持原有登录要求。页面上的姓名、证件类型、脱敏证件号和提交结果均来自 Casdoor 目标用户记录。

### 4. 回调与记录

提交成功后，更新目标用户的 `id_card_type`、`id_card`、`real_name`、实名认证状态和审核时间等字段；随后按签名链接中的 `redirectUri` 和 `state` 返回 new-api。回调失败不影响 Casdoor 已保存的实名认证记录。

## 安全与错误处理

- 继续使用现有签名算法和有效期限制；不接受未签名或签名不匹配的 `userId`。
- 目标用户不存在、组织不匹配、应用不匹配、回调地址非法、nonce/签名失效时，不建立授权上下文。
- 签名跳转链路不返回完整身份证号，只返回既有脱敏信息。
- 普通登录接口和非跳转实名认证接口不改变授权行为。
- 页面刷新期间复用当前有效授权上下文；提交或返回后清理授权上下文。

## 测试要求

- 校验有效签名跳转时，即使当前 Casdoor 会话为空或是其他用户，也能返回目标用户信息。
- 校验失败的签名、过期时间、应用、组织、回调地址和目标用户仍被拒绝。
- 通过跳转上下文查询和提交时，实际更新的是目标用户，而不是当前 Casdoor 会话用户。
- 普通无跳转参数的查询和提交继续要求当前登录用户。
- 提交成功后授权上下文被清理，重复提交不能继续使用已消费上下文。
